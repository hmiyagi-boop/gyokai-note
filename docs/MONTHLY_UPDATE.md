# 月1回の内容アップデート手順

## しくみ

```
① Claude（Claudcord経由）が data/ のファイルを更新
        ↓
② 新しいブランチにコミットして GitHub に送る（push）
        ↓
③ プルリクエスト（PR）を作る ← 「こう変えました」の申請
        ↓
④ あなたが GitHub で差分を確認して「Merge」（スマホのGitHubアプリでも可）
        ↓
⑤ GitHub Pages が自動で再公開（数分）→ スマホ・PCのアプリに反映
```

ポイント：**GitHub が自動で内容を更新するわけではありません。**
更新作業をするのは Claude で、GitHub は「変更の記録・確認・公開」を担当します。
④であなたが確認してから反映されるので、誤った情報がそのまま載るのを防げます。

## 事前準備（初回だけ）

Claudcord が動いているPCで、次の2つができている必要があります。

1. このリポジトリが clone（コピー）されている
2. `gh auth login` で GitHub にログイン済み（push とPR作成ができる）

## Claudcord に送る依頼文（コピーして使う）

```
業界理解ノートの月次アップデートをして。
リポジトリ：<このリポジトリのフォルダの場所>

1. main を最新にして、update/YYYY-MM のブランチを作る
2. data/industries.js の各業界について、直近1か月の主要ニュース・法改正・統計の更新を調べる
   - trends に新しい動きを追加（period に年月、impact に経営への影響）
   - 古くなった数値（市場規模・利益率など）があれば更新
   - 出典をPRの説明に箇条書きで残す
3. 余裕があれば新しい業界を1つ追加（既存業界と同じ項目をすべて埋める）
4. window.DATA_UPDATED_AT を今月にする
5. コミットして push し、PRを作成。PRのURLを返して
```

## 確認するときのチェックリスト

- [ ] 数値に出典があるか（PRの説明に書かれているか）
- [ ] 「最近の動き」が、営業トークで使える内容になっているか
- [ ] お客様の社名・機密情報が入っていないか（公開リポジトリの場合は特に注意）
- [ ] プレビューで画面が崩れていないか

## さらに自動化するなら

Claude Code の「スケジュール実行」を使うと、毎月1日に上の作業を自動で行い、
PRだけが届く状態にもできます（確認とマージはあなたが行う）。
